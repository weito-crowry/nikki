# 01_overview.md

## 概要

本プロジェクトは、OpenAIのエクスポートデータ（ZIP形式）を入力とし、
ユーザーの活動ログから「日記」を自動生成するCLIツールを構築するものである。

生成される日記は以下を含む。

-   ユーザーがその日に興味を持った事
-   ユーザーがその日に抱いた疑問
-   解決された内容およびその結末
-   生成された画像（存在する場合）

出力形式は以下を想定する。

-   Markdown
-   HTML
-   PDF

------------------------------------------------------------------------

## 入力 / 出力

### 入力

-   OpenAIエクスポートZIP
-   conversations JSON群
-   生成画像（dalle-generations）
-   添付画像

### 出力

-   日記（Markdown / HTML / PDF）
-   中間生成物（JSON）

------------------------------------------------------------------------

## 設計方針

### 1. タスク分解戦略

処理は以下の2種類で分離する。

  種類       粒度
  ---------- ----------------
  非AI処理   粗くまとめる
  AI処理     細かく分割する

理由：

-   AI処理はコストが高いため再実行粒度を小さくする必要がある
-   非AI処理は再現性が高く一括処理で問題ない

------------------------------------------------------------------------

### 2. 再実行（レジューム）前提設計

本システムは以下を前提とする。

-   任意のタスク単位で再実行可能
-   中断後の再開が可能
-   完了済み処理は再利用

再実行判定は以下に基づく。

-   入力ハッシュ
-   プロンプトハッシュ（AI）
-   モデル
-   スキーマバージョン

------------------------------------------------------------------------

### 3. キャッシュ前提設計

AI処理はキャッシュ可能とする。

キャッシュキー：

-   モデル
-   プロンプト
-   入力データ

これにより以下を実現する。

-   同一処理の再実行回避
-   トークン消費削減
-   開発時の試行効率向上

------------------------------------------------------------------------

### 4. JSON成果物中心設計

すべての中間成果物はJSONで保存する。

理由：

-   後段処理で再利用可能
-   スキーマ検証が容易
-   デバッグ容易性向上

最終出力のみMarkdown/HTML/PDFとする。

------------------------------------------------------------------------

## 非目標

本プロジェクトでは以下は対象外とする。

-   リアルタイム処理
-   分散処理
-   データベース運用（初期段階）
-   完全自動最適化

------------------------------------------------------------------------

## 用語定義

### run

一連の実行単位

### task

処理単位（例：ai.extract_findings）

### item

タスクの対象（thread / unit / entry）

### artifact

タスクの出力成果物

### unit

集約単位（例：日単位）

### entry

日記1件

------------------------------------------------------------------------

## 全体構造

処理は以下のステージで構成される。

-   prepare
-   analyze
-   ai.catalog
-   ai.thread
-   ai.unit
-   ai.entry
-   render

------------------------------------------------------------------------

## 設計上の重要原則

1.  AI処理は必ず分割する
2.  thread単位の成果物を最重要とする
3.  unit処理はthread成果物のみを利用する
4.  日記生成と整形は分離する
5.  状態管理はファイルベースで行う

------------------------------------------------------------------------

## まとめ

本システムは以下を実現する。

-   再実行可能なパイプライン
-   AIコスト最適化
-   高い可観測性（progress / events）
-   拡張可能な設計
